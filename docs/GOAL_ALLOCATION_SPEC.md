# Goal & Allocation Planner — first release

Scope: target wealth/date, monthly contribution, ETF target weights, current-weight comparison, two buy-only scenarios, approval, paper execution, durable PC ledger and next-month reuse. Existing actual holdings/order readers, CSV performance and Strategy Lab remain separate. Full attribution, verified historical goal adherence and real order execution are future work.

Data: actual holdings may be copied as an explicitly hypothetical starting portfolio. Broker cash is unknown: require user-confirmed virtual cash. Supported base/asset currencies KRW/USD; mixed assets require a user-confirmed fixed KRW per USD assumption. Prices are fixed user-confirmed references (source/date shown), not executable quotes. Quantities up to six decimals, a positive lot size per asset, base cash in whole won/cents. Unsupported existing products remain frozen, with target zero; the selector contains a limited ETF universe. No silent investment goals/default personal portfolio.

Goal: future deposits from next month; this month's contribution enters current wealth only after its separate paper execution. An explicit contribution start month can defer deposits. End-of-month deposits and constant annual compound return converted to monthly rate. Show paid-in capital, assumed growth, required rate (search range -99.99% to 1000%), and required monthly deposits under the selected assumption. No forecast probability, historical return or guarantee. Ongoing fund expenses must be reflected in the user's net return assumption; transaction costs apply separately to current purchases.

Allocation: existing cash cannot fund purchases. Scenario A splits the new contribution by targets; scenario B projects target-value gaps onto a budget-bounded nonnegative simplex. Both reserve target cash, conservatively cap new purchases by maximum position weight after estimated costs, round quantities down to lot sizes and round debits/fees up to base money units. Report actual remaining deviations, fees and rounding. This bounded heuristic is not a global integer optimum. No forced selling or automatic target changes. Any remaining cash/position-limit violation or reference price older than seven days blocks approval/execution.

Approval: server independently recalculates; freezes goal version, quote assumptions, plan, reason and hash. Setting/price changes increment the ledger revision and invalidate prior approvals. Execution rechecks revision, month, hash and constraints. One contribution/execution per ledger per KST month, including an all-cash plan. Repeating the same approved execution returns its existing result. New-month plans use the executed holdings/cash. Missing market movement remains an explicit valuation assumption until prices are updated.

Persistence: guarded loopback bridge with exact Origin/Host and existing one-time remote pairing; no Vercel financial persistence. Each ledger is one atomic JSON replacement under the private history directory / investments. Exclusive per-ledger lock blocks overlapping mutations. A crashed process may leave a lock: verify the server is stopped before removing that specific lock; never auto-delete it during execution. No database-grade tamper resistance or encryption claim. PC backups remain the user's responsibility. Browser profiles are not financial account authentication/isolation. Demo is synthetic and memory-only, clearly distinguished from PC storage.

Validation: deterministic goal math, FX direction, fees, lot/cash constraints, frozen positions, invalid inputs; atomic persistence/reload, stale revisions/approval, idempotency, concurrent attempts, cloud/public-directory denial, and synthetic browser goal → comparison → approval → execution → reload. Packaging must exclude all runtime ledgers and credentials.
